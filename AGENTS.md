# Инструкции проекта

## Обязательная процедура создания коммита

Перед каждым `git commit` или `git commit --amend`:

1. Повторно прочитай раздел «Именование коммитов» ниже.
2. Получи имя текущей Git-ветки и проверь сообщение коммита на соответствие указанному формату.
3. Не создавай коммит, если сообщение не соответствует формату.

## Именование коммитов

Используй следующий формат названия коммита:

```text
<ветка>:<описание изменений на английском>
```

Вместо `<ветка>` указывай имя текущей Git-ветки. Описание изменений пиши на английском языке.

Пример:

```text
feature/campaign-products:Add editable product margin settings
```

## Актуальность README

При изменении конфигурации, структуры, команд, потоков данных или поведения,
которые уже описаны в `README.md`, обязательно обновляй соответствующий раздел
README в рамках той же задачи.

Не добавляй в README детали, которых нет в фактической реализации. Перед
завершением работы сверяй изменённую реализацию с существующим описанием.
